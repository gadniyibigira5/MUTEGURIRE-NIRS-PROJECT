# AI assistance and originality disclosure

## AI assistance used

AI tools were used as assistants for code generation, extraction-script scaffolding, troubleshooting support, comparative review, and drafting or reorganizing documentation. The team must verify the final code and content and remains responsible for the project's data, methods, interpretations, security, and claims.

The optional API-backed chat feature calls an existing language model when configured with a server-side provider key. **This is not a custom model trained by the Mutegurire team.** The default rule-based assistant computes a limited set of answers from the local district table. The PDF endpoint extracts candidate rows heuristically and does not update the live dataset.

## Human review responsibilities

Before submission, the team should:

1. Run the application and inspect every new feature.
2. Review all generated code and understand the main data flow.
3. Verify source publications, figures, definitions, calculations, and attributions.
4. Remove claims that cannot be supported by the running product or source evidence.
5. Check that API secrets are not committed or exposed in browser bundles.
6. Complete any competition declaration truthfully and only if the team can confirm it.

## Originality and rights

The team must describe the work as its own only to the extent that this is truthful, acknowledge every external source and reused component, and comply with the current NISR competition terms. The official competition page states that AI use is permitted only with disclosure and that submitted work is subject to the intellectual-property terms specified by NISR. The team should read and accept those terms itself; this document is not a substitute for that review.

Source: [Official NISR hackathon rules](https://statistics.gov.rw/about/hackathon/2026-hackathon-competition).
