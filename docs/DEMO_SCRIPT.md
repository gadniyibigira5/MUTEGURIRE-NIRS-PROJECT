# Three-minute demo script

This script is a suggested presentation sequence. Adapt it to the deployed build and do not demonstrate features that are not working in that build.

## 0:00–0:25 — Problem and purpose

“Mutegurire is a district-level maternal and child health planning prototype for Rwanda. It brings selected indicators into one view so planners can compare districts and see where the evidence is incomplete. It is a descriptive decision-support tool, not a predictor or automatic allocator.”

## 0:25–1:05 — Explore the map

1. Open the district map and explain the selected indicator and colour/rank relationship.
2. Select a district and show its profile.
3. Point out a validation status and explain that single-source means not yet independently cross-checked.
4. Select a district or indicator with missing values and show that the app does not replace missing with zero.

## 1:05–1:40 — Compare and plan

1. Open the insight/comparison view.
2. Explain that a pattern is descriptive and does not establish causation.
3. Open the outreach scenario and change the hypothetical team count.
4. State that this is an illustrative scenario, not an evidence-validated staffing or budget recommendation.

## 1:40–2:15 — Ask Mutegurire

Ask a supported question about district ranking, comparison, missing data, or the method. Explain whether the response is generated by the local deterministic assistant or the optional model-backed service in this deployment. Do not call the existing model a custom-trained model.

## 2:15–2:40 — PDF evidence workflow (only if deployed and tested)

Upload a non-sensitive text-based report, show extracted candidates with page references, and explain that each candidate requires human review. Explicitly show that upload does not automatically publish data to the dashboard.

If the API is not deployed or this workflow has not passed a test, skip this segment and state that PDF ingestion is a planned extension rather than a live production feature.

## 2:40–3:00 — Impact and limitations

“Mutegurire's immediate contribution is making district comparisons and data gaps easier to inspect. Our next step is source-by-source verification, followed by a reviewed update process and stakeholder testing. We avoid presenting uncertain estimates as official counts.”

## Presenter checklist

- [ ] Open the public app before recording.
- [ ] Confirm network access and API health if needed.
- [ ] Use one or two known districts and one known missing-data example.
- [ ] Keep the demo under the organizer's time limit.
- [ ] Do not show keys, private files, terminal secrets, or unverified target claims.
- [ ] Keep the demo video in the repository or link it from README after recording it.
